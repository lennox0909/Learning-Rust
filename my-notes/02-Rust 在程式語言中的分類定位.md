# Rust 在程式語言中的分類定位

若用一句話概括，Rust 屬於一種**「靜態強型別、編譯式、多典範的現代系統程式語言」**。

在電腦科學中，程式語言可以從多個不同維度來分類，以下是 Rust 在各個維度中的詳細歸屬：

---

## 1. 依「抽象層級與用途」分類：系統程式語言（Systems Programming Language）
* **定位**：與 C、C++、Zig 同屬系統級語言。
* **特色**：能夠直接操作底層記憶體與硬體資源，且不需要龐大的執行期環境（Runtime），因此適合用來開發作業系統核心、驅動程式、瀏覽器引擎、資料庫與嵌入式系統。
* **特別之處**：雖然它能進行低階控制，但也提供了非常現代化的高階抽象語法，因此常被視為兼具「低階效能」與「高階表達力」的語言。

---

## 2. 依「執行方式」分類：編譯式語言（Compiled Language）
* **定位**：與 C、C++、Go 相同（相對於 Python、JavaScript 等直譯式語言，或 Java、C# 等依賴虛擬機的語言）。
* **特色**：Rust 程式碼會透過編譯器（`rustc`，底層主要使用 LLVM）直接編譯成目標平台的**原生機器碼（Native Machine Code）**。執行時不需要額外的直譯器或虛擬機，因此啟動速度快、執行效能極高。

---

## 3. 依「型別系統」分類：靜態型別、強型別（Statically & Strongly Typed）
* **靜態型別（Static Typing）**：所有變數的型別都必須在**編譯時期**確定，這能讓編譯器提前捕捉大量的型別錯誤。不過 Rust 具備優秀的**型別推導（Type Inference）**能力，開發者不必每次都手動寫出型別。
* **強型別（Strong Typing）**：Rust 不允許隨意進行隱式型別轉換（例如不能直接將整數與浮點數相加，必須明確轉型），以此避免潛在的精度遺失或邏輯錯誤。
* **進階分類**：在程式語言理論中，Rust 的所有權系統屬於**仿射型別系統（Affine Type System）**（每個資源最多只能被使用/轉移一次），這是它與傳統靜態型別語言最大的差異。

---

## 4. 依「程式設計典範」分類：多典範語言（Multi-paradigm）
Rust 並不拘泥於單一典範，而是吸收了多種語言的優點：
* **指令式 / 程序式（Imperative / Procedural）**：支援傳統的迴圈、條件判斷、函式與可變狀態控制。
* **函數式（Functional）**：深受 OCaml、Haskell 等函數式語言影響，具備預設不可變性、閉包（Closures）、高階函式、迭代器（Iterators）、代數資料型別（`enum` 與 `struct`）以及強大的模式匹配（`match`）。
* **物件導向特性（Object-Oriented，但非傳統繼承）**：Rust **沒有**傳統的 `class` 與類別繼承（Class Inheritance），而是透過 `struct` 封裝資料、`impl` 定義方法，並用 `trait`（類似介面）實現多型，強調「組合優於繼承（Composition over Inheritance）」。
* **泛型與元程式設計（Generic & Metaprogramming）**：支援零成本的泛型程式設計，以及強大的編譯期巨集（Macros）。

---

## 5. 依「記憶體管理方式」分類：編譯期自動管理（無 GC）
* 傳統上語言分為「手動管理（C/C++）」與「垃圾回收 GC（Java/Go/Python）」兩大陣營。
* Rust 開創了第三條路：承襲 C++ 的 **RAII（資源取得即初始化）** 概念，並結合**所有權與借用檢查機制**，由編譯器在編譯時期自動決定何時釋放記憶體，既不需要開發者手動 `free`，也不需要執行期的垃圾回收器。

---

| 分類維度 | Rust 的歸屬 | 類似的常見語言 |
| :--- | :--- | :--- |
| **定位與層級** | 系統程式語言 | C, C++, Zig |
| **執行方式** | 編譯式（原生機器碼） | C, C++, Go |
| **型別檢查時機** | 靜態型別（含型別推導） | C++, Java, TypeScript, Go |
| **型別嚴格度** | 強型別 | Haskell, Python, Swift |
